# Quality and API changes, 14 November 2026

This dated guide maps the current maintenance changes to their contracts and checks. It is not a
production-maturity certificate. Start with the [architecture](ARCHITECTURE.md) and
[invariant map](INVARIANTS.md) when changing an implementation.

## Public API decisions

- Use `LanguageView.field(name)` for a literal field name, including names containing `/` or `~`.
  Use `item(index)` for a Blue list item. Keep `at(pointer)` for an explicit JSON Pointer.
- Keep an authoring editor inside its callback and creating thread. It expires after success or
  failure; retaining it does not retain an independent mutable document. Explicit Blue null is a
  value; Java null is rejected at these authoring boundaries.
- A durable host may restore a protected predecessor once, inspect its receiving channels, then
  call `Contracts.Execution.processRestoredLocal` with that same state. The state belongs to the
  open execution. This saves duplicate restoration; ordering, authority and conditional durable
  publication remain the host's responsibility. Existing Map-based entry points remain available.
- A shared provider owns its thread safety and I/O deadlines. Missing or failed evidence is not a
  proof of absence. See [provider contracts](../src/main/java/blue/LanguageProvider.java).

The declaration guard preserves existing public/protected API and rejects abstract-method
additions to existing types. It does not prove behavioral compatibility, overload disambiguation
or independent specification conformance. See [API policy](../api/README.md).

## Memory and verification decisions

Small JSON reads no longer inherit field-name dictionaries grown by unrelated documents.
Arbitrary-precision cache values account for physical magnitude and retained decimal rendering;
an oversized valid value can be used without being retained. Nested runtime bindings in restored
checkpoints are frozen, so caller mutation cannot alter a validated state afterward.

Package evidence sharing happens only after an archive passes independent verification. Equal
immutable bodies and proofs may share storage; provider responses share only when their complete
envelopes match. A warm dependency cannot authenticate a forged new carrier. Different valid
spellings and cyclic owning sets remain intact. There is no global interner. The loader's byte
budget counts source bytes, not total JVM heap. See the [package architecture](ARCHITECTURE.md#sharing-verified-package-evidence).

The host's full 41-package catalogue probe measured approximately 173 MB of retained heap after
requested collection, compared with 1.158 GB before evidence sharing. The old measurement used a
larger heap; this is retention evidence, not a matched startup-speed or throughput comparison.
The host retains a separate executable guard for that catalogue.

## Maintenance checks

```bash
./gradlew build errorProne jacocoTestCoverageVerification
./gradlew nativeReadBudgetProbe executionRetentionProbe languageInputAllocationProbe numericCacheRetentionProbe
```

The ordinary suite contains 2,814 tests at this revision. The allocation/retention probes run in
explicit JVMs and remain separate from test counts. The API checker has 18 independently compiled
fixtures; a declaration snapshot alone cannot catch its own parser mistakes.

Use deterministic clocks and explicit overlap barriers when reproducing failures. Keep the
failing counterexample, then compare the same input and completion boundary. These follow the
[testability and ownership principles](INVARIANTS.md#apply-the-design-references-deliberately)
used as inspiration from Caffeine; its cache throughput is not a baseline for Blue execution.

The remaining gaps include independent conformance/security review, stable releases and licensing,
operating history and size-dependent physical work for wide canonical maps. Constant semantic gas
or a constant number of active owners does not imply constant hashing, allocation or latency.
